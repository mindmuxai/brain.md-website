Why brain.md

Not a README.
Not a memory dump.

Every project already has a README.md for humans and an AGENTS.md for AI coding tools. Neither stores why decisions were made.

A project brain stores decision-grade knowledge — conclusions that have been reviewed, structured, and are authoritative enough to guide downstream reasoning and code generation. It lives in a brain/ folder, ships with your repo, and needs no special parser.

File Audience Purpose
README.md Humans Quick start, contribution guide
AGENTS.md AI coding agents How to work on this codebase
brain/ AI reasoning agents + humans Decisions, tradeoffs, rationale — ready for downstream agents

Structure

Six root views.
Unlimited knowledge pages.

Root pages represent the six project-wide views — background, architecture, data flow, feature space, stack decisions, and roadmap. Rewrite them freely; history lives in git.

pages/*.md are granular, append-safe knowledge units. Each tracks the current best understanding (compiled_truth) and the full evidence chain (timeline).

background.md — why this project exists
architecture.md — system shape & modules
stack.md — technology choices & rationale
roadmap.md — milestones & sequencing
brain/ ├── brain.md ← entry point ├── background.md ├── architecture.md ├── flow.md ├── mindmap.md ├── stack.md ├── roadmap.md ├── pages/ │ ├── auth-strategy.md │ ├── db-choice.md │ └── api-versioning.md └── skills/ └── deploy.md

Page Format

compiled_truth +
append-only timeline.

Every page in pages/ has two sections. compiled_truth is the current authoritative answer — rewrite it freely as understanding evolves.

The timeline is append-only evidence. When a conclusion changes, add a reversal entry — the old truth stays in the record.

Timeline event kinds: decision, observation, source, reversal.

Cross-references use the syntax [page-id](mindmux:wiki/page-id) where page-id matches the frontmatter id field exactly. Root pages are referenced by filename without extension: architecture, stack, etc.

pages/auth-strategy.md
--- id: auth-strategy title: Authentication Strategy category: decision status: active created: "2024-09-10" updated: "2024-12-01T09:15" ---   ## compiled_truth Use JWT with short-lived access tokens. Session cookies ruled out for API-first clients. See [api-versioning](mindmux:wiki/api-versioning).   ## timeline - time: 2024-12-01T09:15 kind: reversal summary: Dropped OAuth — scope creep source: internal-review-2024-12 affects: [auth-strategy, stack] evidence: "OAuth adds 3 external deps"

Agent Loading Protocol

Structured context
for any coding agent.

When a coding agent starts on a project with a brain/ folder, it follows a defined loading protocol: read entry point, load relevant root pages, filter pages/ by category and tags, follow cross-references on demand.

The brain tool (e.g. MindMux) can assemble a structured context package — task intent, constraints, rejected options, and acceptance criteria — and inject it before execution begins.

Works with Claude Code, Codex, Cursor, and any agent that can read files.

brain_context: task_intent: "Add payment flow" root_pages: - architecture.md - stack.md pages: - id: auth-strategy section: compiled_truth - id: api-versioning section: compiled_truth constraints: - "Use existing Postgres instance" - "No new external auth providers" rejected_options: - "Stripe Checkout (too opinionated)" open_questions: - "Webhook idempotency strategy TBD" acceptance_criteria: - "Idempotent webhook handling"
