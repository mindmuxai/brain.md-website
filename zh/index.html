为什么是 BRAIN.md

不是 README。
也不是记忆倾倒。

每个项目通常已经有面向人的 README.md， 以及面向 AI 编码工具的 AGENTS.md。 但它们都不负责记录决策背后的 为什么。

项目大脑存储的是 决策级知识： 经过审查、结构化，并且足够权威，可以指导后续推理和代码生成的结论。 它位于 brain/ 文件夹中，随仓库一起交付。

项目根目录中的一个 BRAIN.md 是协议入口： 任何读到它的编码代理都知道如何使用这个项目大脑。 不需要运行时服务，也不需要 MCP 服务器；只有普通文件约定和一个零依赖 CLI。

文件 读者 用途
README.md 人类 快速开始、贡献指南
AGENTS.md AI 编码代理 如何在这个代码库中工作
BRAIN.md 任何编码代理 协议入口：如何读写项目大脑
brain/ AI 推理代理 + 人类 决策、权衡和理由，可直接服务后续代理

结构

六个根页面。
无限知识页面。

六个固定根页面覆盖项目级视角：背景、架构、 流程、思维导图、技术栈和路线图。它们只会被更新，不会被重复创建， 也不携带 timeline：它们的历史由 git 记录。可以使用 mermaid 图让内容更直观。

pages/*.md 是细粒度、可安全追加的知识单元， 归属于五类之一：decision, concept, project, person, reference. 每个页面同时记录当前最佳理解（compiled_truth） 和完整证据链（timeline）。

页面格式

compiled_truth +
只追加 timeline。

pages/ 中的每个页面都有两个部分。 compiled_truth 是当前权威答案； 随着理解变化，可以自由重写它。

timeline 是只追加的证据记录。 当结论改变时，update-truth 会原子地重写 compiled_truth，并追加一个 decision 条目。旧结论仍保留在记录中。

Timeline 条目类型包括：decision, evidence, reversal, note。重写 compiled_truth 和追加对应的 decision 条目会在一次原子写入中完成； 不能只做其中一件。

交叉引用使用 wiki-link 语法： [[page-id]] 其中 page-id 必须与 frontmatter 的 id 字段完全匹配。 运行 brain lint-links 可以确认每个链接都能解析。

工具集

安装一次。
任何项目都有大脑。

这是一套安装优先的工具集，而不是某个项目大脑本身。 运行一次 ./setup，它会把技能软链接到检测到的每个代理中： 目前包括 Claude Code (~/.claude/skills) 和 Codex (~/.codex/skills)。

然后在任何项目中运行 brain-setup： 它会搭建 BRAIN.md 和 brain/ 骨架，并把 CLAUDE.md / AGENTS.md 接入协议。 随后 brain-bootstrap 会从代码、文档和 git log 中播种真实知识；也可以通过访谈来捕获。

四个技能负责具体工作：brain-setup, brain-bootstrap, brain-page（携带 CLI），以及 brain-ingest。

# 1. 全局安装一次工具 ./setup # 2. 让你的代理运行这些技能 # /brain-setup → 搭建 BRAIN.md + brain/ # /brain-bootstrap → 从代码和 git 播种知识 # 3. 接入 brain CLI brain() { node skills/brain-page/bin/brain.mjs "$@"; } # 4. 只通过 CLI 读写 brain ls brain cat db-choice brain create-page --id db-choice \ --category decision --title "Use Postgres" echo "the new understanding" \ | brain update-truth --id db-choice \ --summary "why it changed" brain reindex && brain lint-links

开始使用

给你的 AI 代理一个项目大脑。

1
克隆工具集
下载一次即可。工具集存在于你的机器上，而不是绑定在某一个项目里。
$ git clone https://github.com/mindmuxai/brain.md $ cd brain.md
2
全局安装
把四个技能软链接到每个检测到的代理中，包括 Claude Code、Codex 和任何兼容代理。
$ ./setup → 已安装 4 个技能到 ~/.claude/skills → 已安装 4 个技能到 ~/.codex/skills
3
搭建项目大脑
在你的编码代理中打开项目并运行 setup 技能。它会创建 BRAIN.md 和 brain/ 骨架。
# 在你的编码代理中（Claude Code、Codex...） /brain-setup
4
播种知识
Bootstrap 会读取代码、文档和 git log，用真实决策填充项目大脑；也可以通过访谈来捕获知识。
/brain-bootstrap → 读取代码 + git log → 向 brain/ 写入结构化页面

FAQ

常见问题

BRAIN.md 是什么？

BRAIN.md 是一种在仓库中存储项目知识的普通文件约定。它为代理和人类提供一个可预测的位置，用来查找决策、理由、约束和当前项目上下文。

BRAIN.md 与 README.md 或 AGENTS.md 有什么不同？

README.md 通常说明如何理解或使用一个项目。AGENTS.md 通常告诉编码代理如何在仓库中工作。BRAIN.md 指向项目大脑：关于决策原因、当前事实和未来工作上下文的结构化知识。

BRAIN.md 与 MCP 有什么不同？

MCP 是把工具和上下文提供方连接到 AI 应用的协议集成层。BRAIN.md 不是运行时协议，而是仓库本地的 Markdown 约定加一个小型 CLI，让项目知识保持可读、可审查，并由 git 版本化。

为什么要分离 compiled_truth 和 timeline？

compiled_truth 记录某个主题当前最可靠的理解。timeline 记录形成该理解的证据、决策、反转和备注。二者分离后，代理可以快速读取当前答案，同时在需要审计时保留推理历史。
